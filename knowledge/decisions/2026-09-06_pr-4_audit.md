## Alternatives considered

- Reading credentials and polling a provider endpoint was rejected because it
  violates the central credential-free constraint.
- A persistent App Server was rejected because a short-lived post-turn process
  has a smaller lifecycle and failure surface.
- Pinning the resolved versioned Codex executable was rejected because CLI
  upgrades can remove that release; the snippet retains the stable launcher.
- Merging with inaccessible image-only labels or undocumented hook trust was
  rejected because both create concrete user-facing failures.

## Consequences

- Codex refreshes after completed turns only when its printed `Stop` hook is
  installed, enabled, and trusted; the app's 30-second timer only rereads the
  snapshot.
- Snapshot percentages and timestamps retain inherited local file permissions,
  recorded as a nonblocking LOW hardening opportunity.
- Actual async-hook cancellation behavior and native VoiceOver output remain
  appropriate post-merge observational checks.
